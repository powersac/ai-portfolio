Personal Agent Operating System

An inbox that arrives already triaged

Problem

Email and a to-do list grow faster than one person can clear them, and most of the work inside them is sorting, digging and drafting.

How AI is used

Every morning an agent reads the whole inbox, archives what does not need me and sends back takeaways on each newsletter. For everything else it opens the attachment, checks my calendar and reads the source for the real deadline, then recommends a call with a confidence level. I answer in one word: Draft, Research, Mine, Kill or Park. Decisions land as Gmail drafts, Calendar holds and Todoist tasks, sorted by area. On Fridays it reshapes next week's Todoist queue from my job search pipeline. Nothing is sent or created without my yes.

Result

I start with the sorting and digging done and spend my time on decisions. The instructions live in a Drive doc and a git repo, not in app settings, so every session runs the same playbook. Next step, not built yet: tag a Todoist task @agent and the agent preps it and hands it back as @review.

Business Development

A go-to-market engine

Problem

Personalization at the level of a CEO's top five accounts, for every lead, without a bigger team.

How AI is used

Claude Code is the interface. Plain-English requests source leads from Apollo, enrich them, write the personalization hook, draft the outreach and move each deal through Pipedrive. Subject-line variants are tracked back to the replies they earned.

Result

Built to take one operator from about 50 leads a week to 500+ across 10+ channels, with every channel measured in FlowMo itself.

Fundraising

Research, intros and the Tuesday memo

Problem

A seed round and a weekly operating cadence both need research, warm-intro routing and follow-up faster than one person can do by hand.

How AI is used

Claude researches funds, scores thesis fit, maps the warmest intro path, preps each meeting, tailors the deck and logs every touch in an 11-stage pipeline. Every Tuesday it pulls Linear and Pipedrive, runs a Q&A with the CEO and writes the memo.

Result

A raise pipeline from raw list to wire, and a three-page weekly memo built from live data instead of recollection.

NGO Operations

Contractor and grant operations portal

Problem

A small NGO ran contractor onboarding, invoices, timesheets and grant compliance by hand.

How AI is used

Two small apps on one database, with the logic in the database and a thin automation layer around it. AI is limited to three grounded calls that answer only from retrieved policy and rates, cite their source and send exceptions to a person.

Result

Every record stays readable in the database or as a PDF in Drive even if every app is switched off, and the client owns every account.

No repository shared: the client owns the code and every account.

Draft Zero · Built for a university lab

Diabetes Research Lab

Spoken figures to a first-draft manuscript

Problem

Finished, figure-ready lab results sit unpublished because nobody has time to write the first draft.

How AI is used

A researcher talks through their figures for about ten minutes. Claude drafts only from what was said and the papers supplied, then checks its own draft sentence by sentence and flags every claim the researcher did not make.

Result

A Word draft in the lab's template plus a gap report. It refuses to invent: there is no Discussion section until the researcher records one.

Job Search

A job search run as an operating system

Problem

A senior search means hundreds of postings across a dozen channels, and a spreadsheet nobody trusts by week three.

How AI is used

Claude Code built it and runs it. Every weekday morning it reads four sources, screens them against my narrative and target profile, logs every rejection with a reason, and drafts the research brief, tailored resume and outreach for each survivor. Nothing is sent on my behalf.

Result

Four sources become about three postings worth my attention. A live dashboard, a Google Sheets CRM and 2,000+ automated tests keep it honest.

Fantasy-Football · Personal, built with Claude

Fantasy Football

Two leagues, a handful of yes or no questions

Problem

Two leagues on two sites, with different rules and opposite goals: a keeper league building for next year and a family league playing to win now. Keeping up with injuries, waivers and trade deadlines in both is a weekly chore.

How AI is used

Claude runs on a schedule, three times a week, with no prompt from me. Each league is a markdown file of rules, scoring, keeper math and that league's goal, and every run reads it first. Claude reads both sites, the injury news and the waiver pool, makes the safe moves itself and turns everything else into a short numbered list with a confidence level on each item. It never adds, drops, trades or messages anyone without my yes.

Result

Each week becomes one list I answer in a line, like “yes 3, 5, no 4.” Deadlines show up on their date as a single decision. Every run and every answer is written to a new log file, so the git history becomes the season.

Household: Groceries

One list, two phones, fifteen seconds

Problem

Two people shopping and planning from one list, on phones where the work network blocks most apps.

How AI is used

One Cloudflare Worker serves the page and a small API over a single store. Each person's link is their credential. A 5am job fills the next ten days of dinners from a rotation.

Kids checklist · Personal, built with Claude Code

Household: Chores

Shared state on four phones

Problem

A paper chart cannot tell two kids and two parents who did what, or what is owed.

How AI is used

An installable React app on a Cloudflare Worker. Each child's link only lets her check off her own tasks, and parents edit tasks, rates and payouts. Simultaneous writes retry instead of overwriting.

Result

Every phone shows the same state, with a weekly earnings summary for the parents.

Patterns across all of it

Every system shows its work.2026-Search logs each rejection with a reason. Draft Zero flags every sentence the researcher did not support.
